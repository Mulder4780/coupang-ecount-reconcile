# 상황판(조직도) UI/UX — 다른 앱에 그대로 시킬 지시문

> 이 파일을 통째로 복사해 다른 세션·다른 앱에 붙여넣는다.
> 이 프로젝트 이름·경로·데이터는 한 군데도 안 들어 있다 — 어디에 붙여도 그대로 돈다.

---

## 붙여넣을 지시문 (여기서부터 끝까지)

아래 명세대로 **"상황판" 화면 하나**를 만들어 줘. 내가 쓰는 앱에 맞춰 데이터만 바꾸고,
구조·색·규칙은 그대로 지켜.

### 0. 이 화면이 무엇인가

**"지금 누가 무엇을 하고 있나"를 한 눈에 보는 상황판**이다. 사람이든 기계(자동 회차·
AI 세션)든 **똑같이 '자리(desk)'** 로 그린다. 목록이 아니라 **자리 배치도**다 —
같은 팀·같은 성격끼리 구역(zone)으로 묶여 있어서, 훑어보면 조직이 보인다.

핵심은 셋이다:
1. **자리 하나 = 사람 또는 프로세스 하나.** 둘을 다른 화면으로 나누지 않는다.
2. **상태는 색과 글자 둘 다로 말한다.** 색만 쓰면 색약인 사람에게는 정보가 없다.
3. **모르는 것은 모른다고 적는다.** 뒤에 자세히 쓴다 — 이게 제일 중요하다.

### 1. 화면 골격

세로 3층이 아니라 **왼쪽 사이드바 + 오른쪽(상단바 + 본문)** 이다.

```
┌────────────┬──────────────────────────────────────────────┐
│            │  상단바 (고정)                                │
│  사이드바   ├──────────────────────────────────────────────┤
│  (고정)     │                                              │
│            │  본문 — 구역(zone) 카드들이 세로로 쌓인다       │
│            │                                              │
│  ─────     │                                              │
│  설정      │                                              │
│  달력      │  ── 맨 아래: 이 화면을 읽는 법 (도움말 문단)    │
└────────────┴──────────────────────────────────────────────┘
```

- 사이드바 폭 **280px**, 본문과 함께 세로 스크롤이 아니라 **각자 스크롤**한다.
- 사이드바 맨 위는 **브랜드 블록**: 원형 로고(48px) + 앱 이름(2줄까지 줄바꿈 허용) +
  그 아래 작은 부제 한 줄.
- 그 아래 **주 메뉴**. 항목마다 아이콘(선 아이콘, 20px) + 라벨.
  - 지금 보고 있는 항목은 **채워진 판**(배경 밝게 + 모서리 12px)으로 표시한다.
    글자만 굵게 하지 말 것 — 훑을 때 안 보인다.
- 사이드바 **맨 아래는 따로 떼어 고정**한다: `설정` · `달력`(또는 앱의 부가 메뉴).
  업무 메뉴와 설정이 섞이면 사람이 설정을 못 찾는다.

### 2. 상단바

왼쪽부터 오른쪽으로:

1. 원형 로고(40px) + **앱 이름**(굵게) / 그 아래 **부제**(작게, 흐리게). 넘치면 `…`.
2. (선택) 가운데에 **제휴/소속 로고 묶음** — 회사 로고 + 고객사 로고를 세로로 겹쳐 놓는다.
3. 오른쪽 끝에 **원형 아이콘 단추 줄**(각 44px, 서로 10px 간격):
   - 새로고침 · 밝게/어둡게 전환 · 검색 · 알림
   - **알림에는 빨간 원형 배지**로 안 읽은 수를 얹는다(0이면 배지 자체를 없앤다).
4. 그다음 **알약 모양 상태 칩**: 왼쪽에 점(●) + 지금 도는 일의 이름. 길면 `…`.
   누르면 그 일의 상세로 간다.
5. 맨 끝에 **초록 점 + 지금 시각**(예: `오후 06:07`). 1분마다 갱신.
   - 이 시계는 장식이 아니다 — **화면이 살아 있다는 유일한 증거**다.
     화면이 멈췄는데 숫자만 그대로면 아무도 모른다.

### 3. 구역(zone) 카드

본문은 **구역 카드**들이 세로로 쌓인 것이다. 구역마다 색이 다르다.

- 모서리 **18px**, 안쪽 여백 **20px**, 배경은 **그 구역 색을 아주 옅게**(불투명도 8~12%),
  테두리는 같은 색 25% 정도. 꽉 찬 색을 쓰지 말 것 — 안에 든 카드가 안 보인다.
- 구역 머리줄: **왼쪽에 구역 이름**(굵게), **오른쪽에 부제**(흐리게, 그 구역이 무슨
  성격인지 한 줄. 예: `자동화 · 수집 · 코딩`).
- 안쪽은 **자리 카드 그리드**. 폭에 따라 열 수가 바뀐다(아래 반응형 참고).

구역 색 예 (원하는 만큼 늘려도 된다):
| 구역 | 색조 |
|---|---|
| 사무 | 파랑 |
| 현장 | 초록 |
| 자동화·AI | 보라 |

### 4. 자리(desk) 카드 — 이 화면의 핵심

카드 하나의 생김새:

```
┌─────────────────────────────┐
│ (아바타) 이름      [배지] ▭  │   ▭ = 작은 모니터 글리프(오른쪽 위)
│          역할·소속 …         │
│ ● 상태 — 상세 설명 …      ▾ │
└─────────────────────────────┘
        ▁▁▁▁▁▁▁▁▁▁            ← 카드 아래 '책상' 판
```

- **아바타**: 40px 원. 이름 앞 **두 글자**를 굵게. 배경색은 이름을 해시해서 정한다
  (같은 사람은 언제나 같은 색). 사진을 쓰지 않는다 — 없는 사람이 생기면 줄이 어긋난다.
- **이름**: 굵게. 옆에 필요하면 **배지 칩**(`팀장`·`센터장`·`회차` 같은 것).
  배지는 알약 모양, 작게, 구역 색 계열로.
- **역할·소속**: 한 줄, 흐리게, 넘치면 `…`.
- **상태 줄**: `● 상태낱말 — 상세` 형식. 점 색과 **낱말을 함께** 쓴다.
- **오른쪽 끝 ▾**: 누르면 카드가 펼쳐져 그 자리의 상세(최근 활동·맡은 일·바로가기)가 나온다.
- **카드 아래 '책상' 판**: 카드보다 살짝 좁은 둥근 사각형을 아래에 겹쳐 둔다.
  이것 하나로 '목록'이 '자리 배치도'로 읽힌다. 기능은 없고 **의미를 만드는 장식**이다.

카드 규격: 모서리 14px · 테두리 1px(흰색 8%) · 배경 흰색 4% ·
**지금 활동 중인 카드만** 테두리를 그 상태 색으로 바꾼다(그림자를 쓰지 말 것 — 다크에서 안 보인다).

### 5. 상태 색과 낱말 (여기가 규칙의 중심)

| 상태 | 점 색 | 낱말 | 뜻 |
|---|---|---|---|
| 실시간 | 파랑 `#3B82F6` | `실시간` | 지금 돌고 있다 |
| 업무 중 | 주황 `#FF9F0A` | `업무 중` | 사람이 접속해 일하는 중 |
| 정상 종료 | 초록 `#22C55E` | `성공` | 끝났고 잘 됐다 |
| 실패 | 빨강 `#EF4444` | `실패` | 끝났는데 잘못됐다 |
| 오프라인 | 회색 `#8A93AD` | `오프라인` | **접속 기록이 있고**, 그게 끊긴 상태 |
| 모름 | 회색 테두리만(속 빔) | `상태 모름` | **확인하지 못했다** |

★ **`오프라인` 과 `상태 모름` 을 절대 합치지 마라.** 이게 이 화면에서 제일 중요한 규칙이다.

- 접속 기록을 **못 읽었을 때** `오프라인`이라고 쓰면, 화면은 오류 없이
  "이 사람 일 안 한다"고 **거짓말**을 한다. 아무도 그게 거짓인 줄 모른다.
- 그래서 판정은 **세 갈래**다: 접속 중 / 접속 기록이 있고 끊김 / **못 읽음**.
  못 읽었으면 속이 빈 회색 점 + `상태 모름` 이고, 상세에 **왜 못 읽었는지**를 적는다.
- 같은 이유로 **"0건"을 그냥 0으로 보여 주지 마라.** `없음(확인함)` 과
  `확인 못 함` 은 다른 글자를 쓴다.

애니메이션: 실시간·업무 중 점만 **천천히 깜빡인다**(2초 주기). 나머지는 움직이지 않는다.
`prefers-reduced-motion: reduce` 면 **전부 멈춘다**.

### 6. 상호작용

- **누르면**: 그 자리의 상세가 펼쳐진다(카드 안에서 펼치거나, 좁은 화면이면
  아래에서 올라오는 시트).
- **길게 누르면(또는 끌면)**: **같은 구역 안에서만** 자리를 옮길 수 있다.
  구역을 넘어가는 이동은 막는다 — 구역은 조직의 사실이지 취향이 아니다.
  옮긴 자리는 기억한다(기기별로).
- **접기**: 구역 머리줄을 누르면 그 구역이 접힌다. 접힐 때 **건수를 남긴다**
  (`자리 6개 · 펼치기`). 조용히 사라지면 그 구역은 '없는 구역'이 된다.

### 7. 반응형

- **1200px 이상**: 사이드바 고정, 카드 그리드 3~4열.
- **900~1200px**: 사이드바 아이콘만(폭 72px), 그리드 2~3열.
- **900px 미만(폰)**: 사이드바는 햄버거로 감춘다. 카드는 **flex-wrap + 가운데 정렬**로
  깐다.
  - ★ `grid auto-fill` 을 쓰지 마라. 마지막 줄에 빈 칸이 남아서
    **마지막 한 명만 왼쪽에 덩그러니** 붙는다. 줄마다 가운데로 모이게 하려면
    `display:flex; flex-wrap:wrap; justify-content:center` 에
    각 카드 `flex-basis: <고정폭>` 이다.
  - 카드 **안쪽 글자는 왼쪽 정렬 그대로** 둔다. 가운데로 모으는 것은 카드 묶음이지
    글자가 아니다.

### 8. 색·글꼴 토큰 (다크 기본, 밝게도 지원)

```css
:root{
  --bg:#0B1020; --bg-side:#080C18; --panel:rgba(255,255,255,.04);
  --line:rgba(255,255,255,.09);
  --ink:#E8ECF8; --ink-2:#9AA6C4; --ink-3:#6B769B;
  --accent:#4C8DFF;
  --ok:#22C55E; --busy:#FF9F0A; --live:#3B82F6; --bad:#EF4444; --off:#8A93AD;
  --r-card:14px; --r-zone:18px; --r-pill:999px;
  --font-ui: system-ui, -apple-system, "Segoe UI Variable", "Segoe UI",
             "Malgun Gothic", Roboto, "Noto Sans KR", sans-serif;
}
```

- **웹폰트를 쓰지 마라.** 못 받으면 조용히 다른 글꼴로 그려지고, 화면을 열어 보기
  전에는 아무도 모른다. 기기가 제 UI 에 쓰는 글꼴을 그대로 쓴다.
- 글꼴 이름을 **여러 곳에 적지 마라.** `--font-ui` 한 줄이 정본이고, 캔버스로
  그리는 자리(캡처·인쇄)도 그 변수를 **읽어다** 쓴다. 그리는 곳에 이름을 손으로
  적으면 화면만 바뀌고 저장한 이미지는 옛 글꼴로 남는다.
- 밝게 모드는 **토큰만 바꾼다.** 색을 컴포넌트 안에 직접 적지 말 것.
  `:root` 에 밝은 팔레트를 정의하고, 어둡게는
  `@media (prefers-color-scheme: dark)` + `[data-theme="dark"]` 양쪽에서 덮는다.

### 9. 맨 아래 도움말 문단 (빼지 말 것)

본문 맨 아래에 **작고 흐린 글씨로 2~3줄**, 이 화면을 읽는 법을 적는다:
- 자리 상태가 **어디서 온 값**인지 (무슨 기록·무슨 표)
- 무엇을 누르면 무엇이 되는지
- **무엇을 단정하지 않는지** (예: 접속 기록이 없으면 오프라인이라 단정하지 않고
  상태 모름으로 둔다)

이 문단이 없으면 사람은 화면을 **자기 식으로 해석**하고, 그 해석은 대개 틀린다.

### 10. 절대 하지 말 것

1. **색만으로 상태를 말하지 마라.** 반드시 낱말을 같이 쓴다.
2. **못 읽은 것을 '없다'로 그리지 마라.** `모름`을 위한 자리와 글자를 따로 둔다.
3. **접은 것을 숨기지 마라.** 접었으면 건수를 적는다.
4. **웹폰트·외부 CDN·외부 이미지 금지.** 못 받으면 조용히 깨진다.
5. **그림자로 강조하지 마라.** 다크 배경에서 안 보인다 — 테두리 색으로 한다.
6. **목록을 다 깔지 마라.** 자리가 많으면 큰 구역부터 보여 주고 나머지는
   `나머지 N개 펼치기` 로 접는다.
7. **화면이 스스로 이유를 지어내지 않게 하라.** 값이 없으면 "없습니다"가 아니라
   "아직 받는 중입니다 / 못 받았습니다"를 구별해 말한다.

### 11. 만든 뒤 나에게 확인해 줄 것

- 폰 폭(375px)에서 본문 전체 높이가 **몇 화면**인지 재서 알려 줘. 3화면을 넘으면
  접기를 더 넣는다.
- 상태 여섯 가지를 **전부 한 번씩** 띄운 화면을 보여 줘(모름 포함).
- 밝게/어둡게 두 장을 보여 줘.
- 색약 시뮬레이션에서 상태가 구별되는지 — 안 되면 낱말이 제 몫을 하는지.

## (참고) 내가 이 화면에서 실제로 겪은 것

- **'오프라인'과 '상태 모름'을 합쳤더니** 멀쩡히 일하는 사람이 노는 것으로 보였다.
  오류가 안 나서 아무도 몰랐다. 그래서 §5 의 세 갈래가 규칙이 됐다.
- **폰에서 `grid auto-fill`** 을 썼더니 마지막 한 명이 왼쪽에 붙었다. §7 의 flex 로 바꿨다.
- **웹폰트**를 넣었다가 못 받은 기기에서 다른 글꼴로 그려졌는데, 캡처를 카톡으로
  보내고 나서야 알았다. 그래서 §8 이 생겼다.
